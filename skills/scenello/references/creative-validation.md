# Creative evidence and functional state coverage

Before implementation freeze each client brief and a small state matrix: entrance, primary interaction, detail/deep link, reverse navigation, empty/error state, narrow viewport and reduced motion. Distinguish depiction from interaction: a product inspection must change viewpoint or geometry, not rotate a flat photograph and call it 3D. Use original procedural assets honestly when photographs are unavailable; do not label illustration as built architecture.

During evaluation, explicit invocation is diagnostic. Natural selection needs an ordinary prompt and observable tool trace. Separate delegated assisted demonstrations from clean matched agent runs. Self-assessment is not blind review. Do not share generated assets or hints between baseline and skill conditions. Keep failed/unfinished runs and missing comparisons visible.

Test secondary states before polishing the hero: contact validation, selected material synchronization, schedule conflicts/persistence, browser history and reduced-motion chapter readability. When resources prevent a fair comparison, label capability evidence incomplete rather than award the skill a win. Do not broaden a visual-quality claim beyond inspected states.

Validate changed states, not only the entrance: selecting a finish may apply attributes to unintended elements if a broad data selector matches a root/container. Scope controls to their intended semantic elements. Run automated access checks after filters, material changes, dialogs and form review; an initial zero-violation scan does not cover later states.

For motion proof, record and assert actual scroll/camera progress after native input. A completed synthetic gesture with unchanged scrollY is a failed motion test, not a successful recording. Deterministic seeks test geometry separately and must not be presented as natural scrolling.


## Inspect the produced asset, not only the page

A browser element screenshot is a viewport clip: other overlapping DOM elements can appear in it. It is not an isolated canvas buffer. A fallback poster captured this way can bake in headings/navigation, then duplicate the live interface or crop its text on mobile. Inspect every output image directly, then hold the renderer import to inspect real loading and reduced-motion compositions.

For a scene-only WebGL export use an explicitly ASSET-ONLY preserved drawing buffer and canvas serialization after the GPU work completes, or a verified UI-hidden capture that retains intended atmosphere. Do not silently enable preserveDrawingBuffer in production; it has performance implications. Keep raw-buffer parity separate from visible-composition parity. A poster captured at viewport size must not be enlarged to a170vh chapter by background-size:cover; validate the actual framing during handoff, not just the source image dimensions.

## Prove that visitors see the effect

Capture a fresh visit from navigation, including asset readiness, rather than waiting until the entrance is over. Compare intermediate states and watch the actual movement when tools support playback. A nonzero timeline, successful compile or navigation test does not prove visible cinematic motion. Record the tool's viewing limits; sampled screenshots cannot establish smooth playback or owner approval.

For each major scroll handoff, test slow, normal, fast, reverse and paused movement with actual wheel or touch input. Verify camera/object state follows actual scroll position. Resize midway, check the mobile composition and retain usable links, focus and reduced-motion content. Test selected finishes, dialogs and return navigation. Keep technical PASS separate from artistic review. For a small change, validate only relevant states; do not impose a full acceptance matrix or repeated benchmark campaign.
