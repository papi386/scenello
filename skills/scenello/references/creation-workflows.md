# Three entry modes, one working website

## Describe a new cinematic website

Extract the audience, subject, purpose, content, emotional arc, focal object and essential interactions. Resolve ordinary choices autonomously; ask only about indispensable missing assets, facts or external destinations. Write a scene contract: entry hook → anticipation → transformation → useful destination. For each beat specify input, persistent element, camera/object motion, text zone and selectable action. Do not replace requested scroll motion with a recording.

Choose design language and hero composition separately using design-and-heroes.md. Choose production by asset fidelity and actual tool availability. Build useful content/navigation, implement the critical continuous transition and verify mobile intermediate states before decorating later sections. Provide appropriate collection/service/detail/about/contact paths; do not deliver disconnected showreel scenes.

## Build from a reference

Inspect the actual page or authorized local video. Separate observation from inferred implementation. Decompose layout, hierarchy, input mapping, temporal beats, depth, occlusion, shared-element handoff and functional destinations. Reconstruct mechanisms with original or authorized assets adapted to the user's subject. A reference is not permission to redistribute proprietary media/code.

When a register exists, query its private catalog for relevant prompts, documents and links; inspect selected evidence. Preserving every URL does not prove every URL was visited. Follow primary documentation for current APIs and mark blocked/missing sources honestly.

## Reconstruct an existing final website

Current source and rendered acceptance outrank old README files, prototypes and rejected versions. Inspect routes, content data, active imports, animation clocks, responsive overrides and asset manifests. Capture accepted desktop/mobile states before changing anything. Experience-recipes.md is an engineering map, not a substitute for the actual project.

Within the authorized private project, reuse the user's existing source/assets where rights and scope permit. This differs from exporting private material into a public skill. Preserve content, order, routes, prices and functional contracts. Never regress accepted behavior because an old brief specifies something else. Exact reconstruction needs the actual licensed assets, fonts, models and services; missing production capabilities cannot be invented.

## Acceptance contract

Name the critical sequence, lead object, coordinate frame and next real action. Include reverse/fast scroll, touch, resize, reduced motion, asset failure and deep links. Measure a stated baseline, inspect actual visuals/functionality, refine the failed mechanism and report limitations. No skill guarantees identical results from unavailable production assets.
