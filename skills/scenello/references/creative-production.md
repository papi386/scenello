# Creative production gates

Use for substantial new art direction or a rejected cinematic implementation. For a small accepted-design correction, preserve the direction and use proportionate evidence.

## Source → treatment → proof

1. **Source evidence.** Distinguish a candidate URL, an opened page, a rendered interaction, a sampled video frame and actual playback. Record the extent actually inspected. A source inventory, a search result or an article title proves none of the later steps. Use original authorized references first where relevant; inaccessible sources get a failure record and a suitable alternative.
2. **Art direction.** For substantial new work compare up to three directions; for an accepted design keep it. Compare different premises, not palette variants: composition, emotional objective, image/model route, motion subject, camera, destination, typography and mobile reframe. Reject any direction whose essential assets cannot reach the brief's fidelity. Do not force a zero-dependency policy that the user did not request.
3. **Cinematic proof before complete page.** Build the hero, its major transformation and a convincing functional destination. Render desktop/mobile and intermediate/reverse states. A simple shape labeled as a luxury asset is not a valid fidelity substitute. Use licensed photography, original image generation, appropriate rendered assets or real geometry/materials when needed.
4. **Explicit visual decision.** Keep artistic FAIL/NEEDS REVIEW separate from functional PASS. Describe the actual visible defects and revise. Do not finish remaining sections to disguise a failed entrance. Owner approval remains owner approval, not an automated score.
5. **Complete and validate.** Only then build secondary content, navigation, forms/state, reduced motion and failure paths. Record real scroll/navigation videos, not just screenshots. Verify the critical reference mechanism survived mobile adaptation and performance work.

## A compact effect record

For each major effect: source alias or approved public URL; inspected scope/time; observed mechanism; inferred details/uncertainty; chosen production method; persistent subject; user trigger; normalized coordinates/timeline; desktop/mobile framing; concrete implementation file; screenshot/recording/assertion evidence; functional result; artistic result; unresolved issues. Do not list an unvisited source as used. Private media, source paths and raw evidence stay outside a public skill.

## Learned failure checks

- Test actual text/glyph bounds, not only document overflow: an overflow-hidden stage can conceal clipped words while a page-overflow assertion passes.
- Shared-object docking requires explicit coordinate and containment ownership. A card's 100% size must resolve against its intended slot, not a distant positioned ancestor.
- Keep moving subjects in the visible camera frame. Do not interpolate toward an offscreen destination so early that the composition empties halfway through.
- Reserve incoming and outgoing reading zones; do not put the next heading under a moving image.
- Prove material/lighting quality in a rendered frame. A context, shader or render call succeeding is not a quality test.
- Preserve separate immutable evidence per attempt. An overwritten failure screenshot cannot be recovered by writing a plausible later narrative.
- Reuse an accepted element through the transition; do not replace it with a generic fade because it is easier. State when a matched visual clone is used instead of persistent DOM identity.

## Tool choice

Choose CSS/WAAPI for genuinely planar artwork and interface state, Three.js/R3F for meaningful geometry, camera and PBR, Blender for authored model/camera needs, and image generation or licensed imagery for photographic composition. Verify the actual tool/version/license. Keep fallback fidelity intentional. Do not import a proprietary design or its pictures merely because its code is licensed.

For opt-in audit use [action evidence](action-evidence.md). For exact-frame work retain a seekable timeline and test actual transition boundaries. A deterministic seek is complementary to normal-speed playback, not a replacement for it.


## Probe the production backend before completing the site

At the cinematic-proof gate, record a small real startup and moving-frame trace on the intended browser backend. A software WebGL renderer can spend seconds in GPU/commit work even when ordinary scene JavaScript is short. Do not discover that only after building every page. Record the actual renderer, initialization and first live draw; inspect native input progression, not only requested scroll values. This is an early feasibility check, not the final repeated acceptance experiment.

If the main thread waits on GPU/commit work, an OffscreenCanvas worker may protect some DOM work but does not establish smooth visible rendering. Test main, worker and GPU timelines plus actual rendered-state acknowledgements. Keep that experiment separate until pixel fidelity, camera continuity, fallbacks and cleanup pass. A queue of accepted render messages is not a queue of displayed frames. If the chosen production route cannot sustain the intended result, reconsider asset/render strategy openly; never substitute a static tier and call cinematic performance unchanged.

### Finishing a design the owner already accepts

Record the same entrance, interaction and return path before and after. Keep a recoverable source snapshot. Pick a visible landmark that belongs to the subject: a photograph edge, a metal rim, a waterline or the selected print. Give that landmark one motion owner through the handoff. Judge its first frame, trajectory, destination and interruption on a narrow viewport. For a spatial scroll, seek backwards to confirm the camera and lighting return to the same pose. For a program sheet, derive its opening origin from the item the visitor selected. Keep optional tool discovery distinct from an actual invocation or usable result.
