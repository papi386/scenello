# Contributing

Use a feature branch and keep changes scoped. Add a guide only if it changes an engineering/art decision; do not expand the entry point into a catalogue of generic advice. Link new material through the technique index and a realistic task.

Contributions must include origin and rights for every asset. Never commit private reference recordings, client screenshots, personal photos, secrets or internal project documents. Use independent explanations and original code diagrams instead. Keep test artifacts outside the distributable tree.

Run the README checks, inspect meaningful mobile/desktop states, and report performance with environment and sample counts. Do not update screenshot baselines without visual review. Add a regression test for fragile fixes, and record unavailable tools honestly.

Before a future pull request: run the release/history scanner, inspect the complete diff and payload, and use a human reviewer. No auto-deploy, account connection or remote upload belongs in contributor setup. Publication and branch protection belong to the eventual repository owner.
